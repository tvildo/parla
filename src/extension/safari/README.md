# Parla for Safari

Safari runs web extensions from inside an app: this folder is that app (macOS, iOS and iPadOS), an Xcode project
generated by `xcrun safari-web-extension-converter` and kept here. The extension itself is the same source as for
Chrome and Firefox, built with `--browser safari` into `build/extension-safari/`; the project references those files
(it does not copy them).

## Build

On a Mac with Xcode (Safari 18 or later):

```sh
python build.py safari                 # build/extension-safari + the macOS app -> build/safari/Build/Products/Release/
python build.py safari --ios           # also the iOS / iPadOS app (simulator build)
python build.py safari --version 0.2.0 # the app's version (CI passes the release version)
```

On other systems `python build.py safari` builds `build/extension-safari/` and checks it against the project.

Without a team the app is signed to run locally: open `Parla.app` once, then in Safari: Settings > Advanced >
"Show features for web developers", Settings > Developer > "Allow unsigned extensions" (Safari turns this off again when
it quits), Settings > Extensions > Parla. Signed with a team (below), it needs none of that.

## Signing and the App Store

```sh
PARLA_APPLE_TEAM=<team id> python build.py safari
```

signs with that Apple Developer team (Xcode: sign in under Settings > Accounts first). The bundle identifiers are
`cc.parla.Parla` (app) and `cc.parla.Parla.Extension` (extension). To publish: create the app in App Store Connect with
those identifiers, then in Xcode Product > Archive (scheme "Parla (macOS)", then "Parla (iOS)") > Distribute App >
App Store Connect. The build number is derived from the version (`0.1.6` -> 106), so each release uploads a new one.

## When the extension gains or loses a file

The project lists the extension's top-level files and folders one by one (Xcode: Shared (Extension) > Resources).
`python build.py safari` fails if they differ from `build/extension-safari/`. Add the new file in Xcode from
`build/extension-safari/` ("Create folder references" for folders, "Relative to Group", both extension targets
ticked), or remove the old one, and commit `Parla.xcodeproj/project.pbxproj`.

## Differences from Chrome

- No enterprise policy (`storage.managed`) and no update events: the App Store updates the app and the extension with
  it. The background script skips both when the browser doesn't have them.
- Safari asks for the microphone per site; until the user answers, the page (and Parla) waits.
